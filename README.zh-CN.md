[English](README.md) | **简体中文**

> [!IMPORTANT]
> **仅支持 macOS 和 Windows。其他使用端平台一律不支持，包括 Linux、Android、iOS / iPadOS。**

> [!WARNING]

在本机浏览 Telegram 频道，按 ❤️ 或其他表情数量排序，并检索已读取的消息。默认英文界面，可在右上角切换为简体中文；错误信息仅使用英文。Python 后端与原生 JavaScript 前端，没有 CDN 或前端构建步骤。

## 功能

- 拉取结束展示实际读取数、可展示数、跳过原因及提前结束原因。
- 可选保存消息与屏蔽记录，核心重启后恢复本地快照、离线排序和检索。
- 按消息 ID 检查文字、表情与可用性的变化，可查看上次保存的文字。
- 可选保留登录状态，重启后自动恢复；凭据与会话由操作系统保护。
- 列出当前账号已加入的广播频道，包括归档频道。
- 一次历史请求查询频道可见消息总数，无需下载全部消息。
- 按全部或指定表情数量、消息时间排序；支持日期范围、停止拉取及部分结果保留。
- 控制批次请求间隔：0.5、1、2、5、10、30 秒，默认 1 秒，拉取中可调整。
- 按 Telegram `#标签` 过滤，与本地文字检索叠加，保留当前排序。
- 屏蔽箱：单条移入后不参与排序、关键词与标签检索，可单条恢复。
- 跟随系统的浅色 / 深色主题，支持手动切换。
- SOCKS5 / HTTP CONNECT 代理、代理测试、可开关的脱敏诊断日志。
- 可直接在本机运行，或部署局域网入口网站，下载并唤起各电脑自己的核心。

## 直接运行源码

需要 Python 3.9+；日常使用建议选择仍有安全维护的 Python 版本。Node.js 22+ 仅用于前端测试，运行应用不需要 Node.js。

macOS：

```sh
sh run.sh
```

Windows：

```bat
run.bat
```

首次运行创建 `.venv`，从官方 PyPI 安装固定版本并校验 SHA-256。打开 **http://127.0.0.1:8765**，使用自己的 [Telegram API ID / Hash](https://my.telegram.org/apps) 登录；不是 Bot Token。验证码可能发到 Telegram 官方客户端，启用两步验证时还需输入密码。

选择频道后，可先查询总数，再设置拉取数量与速度。当前 Telethon 迭代器每批请求最多 100 条，可能返回更少；选择 2,000 条等总量时会自动继续分批读取。速度控制批次请求的最小间隔，不是每条消息都等待，也不是固定的每秒消息数。实际间隔还受网络耗时影响。拉取中调整会用于后续批次，当前已经开始的等待不会被打断。此能力需要核心 1.4.0，旧核心需重新下载安装；发生 FloodWait 时仍停止并保留部分消息。

排序、标签过滤与文字检索仅针对本次已经获取的内容；检索不会额外请求 Telegram。表情计数是读取时的快照。媒体说明参与检索，不下载媒体，不搜索评论或做 OCR。Stars 不计入普通表情。

网络需要代理时，在连接账号前启用代理，填写实际类型、主机和端口，然后在「连接诊断」中测试。仅支持无需用户名密码的代理。代理失败会停止，不回退到直连。

端口占用时可运行 `sh run.sh --port 8767` 或 `run.bat --port 8767`。关闭浏览器不会关闭核心，终端 Ctrl+C 会退出源码模式。默认不保留登录；是否在重启后恢复取决于「保留登录状态」开关。

屏蔽记录按频道与消息 ID 区分，默认保存在核心会话内；刷新网页或重新拉取同一频道后仍有效。屏蔽箱包含本次会话中所有频道的屏蔽消息，不受普通列表当前关键词或标签的影响。恢复后重新参与当前排序与检索；开启「保存消息到本地」后，屏蔽记录随快照一起保存；未开启时，重启核心会清空。「断开并清除」会注销并删除所有本地保留。此功能需要核心 1.3.0，旧核心需重新下载安装。

## 拉取说明、本地保留与检查更新

核心 1.5.0 增加拉取结果说明：按读取上限、可展示普通消息、服务消息、日期排除、不支持记录、重复记录分别计数，并显示历史结束、日期起点、停止或错误。读取上限包含服务消息，因此读取 2,000 条但仅展示 1,998 条是可能的；以本次实际报告为准。Telegram / Telethon 没有返回的记录无法确认原因，不根据消息 ID 缺号推断删除。

「本地保留」提供两个默认关闭的独立开关：

- **保存消息到本地**：保存每个账号、每个频道最近一次拉取或检查的快照，包括部分结果和屏蔽记录。启用时也保存当前列表；完成、停止、正常退出后自动保存。启动后直接恢复最近快照，也可从已保存频道列表切换，不登录也能本地检索。关闭开关删除所有账号的磁盘快照，当前内存列表仍可使用。
- **保留登录状态**：登录成功后保存 Telegram 授权、API ID / Hash 与代理配置，重启自动尝试恢复。不保存手机号、验证码或两步验证密码；浏览器不保存这些秘密。macOS 使用登录钥匙串，Windows 使用当前用户 DPAPI 加密，不回退明文。系统安全存储不可访问时，开关不能启用或会显示保存失败。网络失败保留授权，可点「重试恢复登录」；授权撤销或失效则要求重新登录。恢复沿用保存的代理，不回退直连。

macOS 数据目录：`~/Library/Application Support/TG-MFG/data`；Windows：`%LOCALAPPDATA%\TG-MFG\data`。消息保存在 `messages.sqlite3`，**消息快照未加密**，具有该用户文件访问权的程序可能读取；Windows 登录文件 `login.bin` 为 DPAPI 密文，macOS 授权在钥匙串内。`preferences.json` 仅含保存开关与账号 ID。升级安装不会复制或覆盖数据目录。

**停止核心**会保留已开启的消息与登录；**断开并清除**会尝试注销 Telegram 授权，删除已保存的登录、全部消息和屏蔽记录。关闭登录保留开关只删除保存的授权，不注销当前仍在使用的会话。删除文件不等于从系统备份或磁盘中安全擦除。

**检查已拉取消息的更新**需要联网登录并能访问频道：以原有消息 ID 每批最多 100 条核对，使用所选请求间隔；文字/标签、表情和其他变化分别计数。文字改变时保留上一次文字供展开查看；新文字用于检索、新表情用于排序。明确返回空消息或服务记录时标记「删除或不可用」，退出普通检索，保留原快照。不返回该 ID、网络失败、权限失效或中途停止时保留旧内容，不推断删除；报告显示已核对数。屏蔽状态保持不变，不通过后台订阅自动同步。

检查更新不会追加新消息；需要新增内容时再执行一次所选范围的拉取，该频道快照会替换为本次结果，不宣称这能证明范围之外的旧消息已删除。不同账号的快照隔离，登录其他账号后不会混入上一账号的消息。前端旧核心会显示升级提示并禁用新开关。

## 网站与安装包

网站只提供页面和 Mac / Windows 下载。访问者在自己的电脑运行核心；浏览器直接与 `127.0.0.1:8765` 通信，服务器不执行 Telegram 登录。

首次从部署的网站下载并解压包，Windows 双击 `install.bat`，Mac 双击 `install.command`。安装器注册固定的 `tg-mfg://start` 入口，之后网站可请求系统唤起核心。浏览器可能要求一次点击或确认。网页不能静默安装软件。

Windows x64 安装包附带官方 Python；Mac 包需要 Python 3.9+，首次安装联网安装依赖。源码仓库不包含编译的 Mac 启动器或 Windows 运行环境；源码可以直接运行，创建安装包请先阅读 [构建说明](docs/BUILD.md)。使用端仅支持 macOS 和 Windows；不支持 Linux、移动端或原生 Windows ARM64，且不提供这些平台的安装包。

## 数据与安全边界

默认 API 凭据、手机号、Telegram 会话、频道与消息仅保存在核心进程内存。主动开启本地保留后，消息写入本机数据库，登录由操作系统安全存储保护；不写入浏览器或网站服务器。浏览器 localStorage 只保存语言、主题和非秘密安装标记。开启诊断后会写入有限大小的日志，记录接口、耗时、错误类型和代理主机 / 端口，排除请求正文、账号凭据及消息。

核心仅监听回环地址，校验 Host、Origin 和随机 API token。网站下载包只允许下载时的指定网站来源连接；网页使用 CSP，消息以 `textContent` 展示。网站及其脚本属于信任边界：配置好的网站有能力访问本机核心 API；部署者需保护网站和 HTTPS。其他本机程序、浏览器扩展及拥有本机访问权限的人不在此隔离边界内。

Telegram 用户会话具有账号权限，服务端没有为本项目授予“只读 token”。代码只调用所需的登录、注销和读取接口。长时间批量读取仍受 Telegram 限流及账号规则约束；遇到 FloodWait 会停止并保留部分结果，没有保证不会受限的消息数量。

“断开并清除”尝试注销当前会话；若注销失败，需在 Telegram 官方客户端的设备管理中移除。开启登录保留时关闭核心不会注销；未开启时正常关闭尝试注销。强制结束进程不代表 Telegram 确认注销。详见 [SECURITY.md](SECURITY.md)。

## 开发与验证

```sh
python -m venv .venv
# macOS；Windows 对应 .venv\Scripts\python.exe
.venv/bin/python -m pip install --require-hashes -r requirements.txt
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
node --test tests/test_*.mjs
```

测试使用模拟 Telegram 客户端与回环代理，不需要真实账号，不访问 Telegram。GitHub Actions 配置 Python 3.9 / 3.13 的离线功能测试，包含 macOS、Windows 与额外的 Linux 测试环境；Linux 仅用于自动化测试，使用端不支持 Linux。工作流需要上传到 GitHub 后才会实际执行。

现有验证涵盖登录状态、计数、拉取、排序与检索、来源保护、安装入口参数限制、诊断脱敏、SOCKS5 / HTTP 握手及 Windows 原生连接语义模拟。Windows 原生注册与唤起仍需完整实机验证；Mac 启动器为临时签名，未公证。依赖哈希与测试通过不等于独立安全审计。
