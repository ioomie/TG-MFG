# Security policy

## Scope and trust boundaries

TG-MFG is intended for your own account, a local core and a controlled private website. It does not provide tenant isolation or a Telegram-issued read-only authorization. **All code was generated by AI and has not received an independent security audit.**

The core binds only to `127.0.0.1`, validates Host / Origin / random API token and has no wildcard CORS. The configured website can obtain the bootstrap token and call core APIs, so compromising that website affects account security. Origin checks restrict browser requests, not local programs that forge headers. Browser extensions and programs/users able to access or modify the installation are outside this boundary.

Credentials and content stay in memory by default. Opt-in local storage uses an unencrypted message database in the current user’s app data directory. Saved Telegram authorization, API credentials and proxy settings use macOS Keychain or Windows **current-user** DPAPI, never machine-wide DPAPI or plaintext fallback. Login codes and two-step passwords are not saved. The security APIs fail without interactive authorization prompts when unavailable.

Programs running as your user may still read message files or use OS credential-decryption facilities. A saved Telegram session is account authorization and must not be shared. Browser storage contains only language, theme and a non-secret installation marker. Process memory, OS dumps, extensions and developer tools are not protected by this design.

Snapshots are isolated by Telegram user ID and channel ID. Update checks mark unavailable only explicit empty/service records, preserving missing/unconfirmed content. Stop core preserves opted-in data. Disconnect & clear deletes saved authorization, messages and blocked records and attempts Telegram logout; failed logout needs session removal in the official app under Devices. Disabling a storage switch deletes its saved data. File deletion is not secure erasure and does not remove backups.

Debug logs are off by default, bounded and redacted when enabled. Proxy addresses and website origins can still reveal private network configuration; review before sharing. Download and build allowlists exclude real configuration, saved data, secrets and logs.

The launcher accepts only the fixed `tg-mfg://start` action, with no arbitrary paths or commands. Websites cannot silently install/run downloaded software. Mac packages are ad-hoc signed and not notarized. Windows native installation, launching and DPAPI require real-machine release checks.

## Reporting

Use the repository’s **Security → Report a vulnerability** if private vulnerability reporting is enabled. Otherwise open an issue without exploit details asking for a private contact channel. Never upload API Hash, phone numbers, login codes, passwords, API tokens, sessions or original messages to a public issue.

For ordinary bugs, include the version, OS/browser and failing steps, plus reviewed redacted diagnostics if useful. **Errors are intentionally English in every interface language.**

## Maintenance

Current core version: **1.6.0**. Recheck dependency advisories before releases. Pinned versions and hashes verify expected files, not freedom from vulnerabilities. Bulk reading remains subject to Telegram limits and account rules; no fixed message count guarantees safety.
